# 販売・請求ハブ デモアプリ 修整項目一覧（第2版）

- 対象: https://readcrew-tbcorporate-demo.vercel.app/
- 出典: 2026年8月14日 15:08 JST 会議FB
- 目的: 請求一覧と入金管理の二重表示を解消し、「1つのデータが1つの画面にしかない」状態に再構築する
- 方針: 複雑なロジックは実装せず、**画面の立付けとUIの見え方**で解決する。デモ共有は月曜目安
- 優先度: R0(データ整理・工数小) → R1(UI微調整) → R2(請求一覧の再構築) → R3(画面統合・影響大) → 保留

## R1 — UI微調整（請求書プレビュー）

### 1-1. トグルのデザイン崩れを修正【指摘事項】
- [ ] スライドスイッチ（ONでつまみが右にずれる形）をセグメントコントロールに変更
- [ ] Before / After の2択、選択側に白いピル。幅が変わらないので不自然な動きが出ない
- [ ] 税抜統一・繰越型の2つとも同じ形に揃える
- 根拠: 「画面右上にある税抜き表示等のラジオボタンの挙動が右側にずれて不自然に動く不具合」

### 1-2. ヘッダーに請求番号・日付を追加
- [ ] 画面ヘッダー（「請求書プレビュー」見出しの横）に請求番号と請求日をバッジ表示
- [ ] 帳票内の記載は現状のまま
- 根拠: 「不足していた『番号』と『日付』の表示を追加する」

### 1-3. 繰越型トグルは残す
- [ ] 削除せず維持。デザインのみ1-1で調整
- 根拠: 実装済みで追加コストがなく、経理の課題#2（差引繰越額の誤解）への直球の回答になるため。会議の「見送り」はロジックの作り込みを指す

## R2 — 請求一覧の再構築（旧・入金管理）

### 2-1. 畳んだ行に3数字を表示【最優先】
- [ ] 行を畳んだ状態で「請求額 / 入金済み額 / 未入金額」を横並び表示
- [ ] 数字は桁揃え（tabular-nums）、未入金のみ赤字
- [ ] ステータスを 入金待ち / 一部入金 / 入金済 の3段階に
- [ ] 行を開くと従来どおり伝票単位の消込
- 根拠: 「複数部署の仕事が統合されて1つの請求書になっている場合、一部だけ入金されるケースがある」

### 2-2. 未入金アラート
- [ ] 入金期日を過ぎて未入金が残る行を強調（左端に赤バー＋淡い赤背景＋日付を赤字）
- [ ] ステータスに「期限超過」を追加
- 根拠: 「入金予定日を過ぎても未入金のデータを、パッと見でわかるように赤く強調表示」

### 2-3. バッジによる絞り込み
- [ ] 画面上部にバッジを配置: 全て / 期限超過 / 一部入金 / 入金待ち / 入金済
- [ ] 各バッジに件数を表示。「期限超過」のみ赤系にして押さなくても件数が目に入るようにする
- 根拠: 「バッジ等のポチポチできるボタンで期限切れの未入金データのみ絞り込める」

### 2-4. KPIカードの差し替え
- [ ] 未請求 / 統合済 / 請求済 → 請求額 / 入金済 / 未入金 / 期限超過 の4枚に
- 根拠: 画面の役割変更に伴う整合

## R3 — 画面統合（影響大・最後に実施）

### 3-1. 売上一覧に「統合して請求書を作成」を移譲
- [ ] 複数室の行にチェック → 「統合して請求書を作成」ボタン
- [ ] 確認ダイアログ（得意先 / 室別の内訳 / 件数 / 合計 / 請求番号）
- [ ] 実行で請求書プレビューへ遷移。伝票ナンバーと明細が並ぶ
- [ ] 得意先が混在した選択はボタンを無効化し「得意先ごとに選択してください」と表示
- 根拠: 「売上一覧から複数の事業部の仕事にチェックを入れて『統合して作成』を実行できるようにする」

### 3-2. 旧「請求一覧」を削除、「入金管理」を「請求一覧」に改名
- [ ] 現 `/billing`（統合画面）を削除し、現 `/payments` の中身を `/billing` へ移設
- [ ] `/payments` は `/billing` へリダイレクト
- [ ] 見出しを「請求一覧〈請求締処理・回収消込〉」に（商蔵語彙の併記を維持）
- [ ] サイドナビから「入金管理」を削除
- 根拠: 「既存の請求一覧画面は削除し、入金管理の名称を請求一覧へ変更する」

### 3-3. 発行で売上一覧から消える動線
- [ ] 請求書を発行した売上は売上一覧から外れ、請求一覧に現れる
- [ ] 「請求書を発行したか」だけを境界にし、同じ行が2画面に並ばないようにする
- 根拠: 「請求一覧と入金管理で同じようなデータが二重に表示されているように見える点を解消」

## R4 — PDFページング（余力があれば対応）

### 4-1. 明細が2ページ以上になっても崩れないようにする
- [ ] 明細ブロックをdivグリッドから実テーブル（`<table>` + `<thead>`）に変更し、印刷時に**列見出しが各ページで繰り返される**ようにする
- [ ] `@media print` で以下を制御
  - 明細1行が改ページで分断されない（`break-inside: avoid`）
  - 小計・合計・お振込先のブロックが分断されない
  - 室ごとのセクション見出しがページ末尾に単独で残らない
- [ ] `@page { size: A4; margin: 15mm }` で余白を固定
- [ ] 画面ヘッダー・トグル・操作ボタンは印刷対象外にする（`print:hidden` の徹底）
- 根拠: 「項目数が多い場合、現状のA4に収まらない可能性がある」。会議では保留となったが、余力があれば対応する
- 注意: **請求の正確な内訳ボリュームが不明**なため、ページ番号の様式（「1/2」の位置・体裁）は仮置き。デモでは適切なデータ量のものを選ぶ前提は変えない
