## 未実装・要検討事項

### セキュリティ・運用上の注意（原文spec該当セクション、いずれのフェーズにも属さず独立対応が必要）

- [ ] **Basic認証またはアクセス制限の追加** — Vercelプロジェクト設定（`vercel.json` の `headers` またはミドルウェアでのBasic認証実装）で対応。公開URLに商流を想起させるデータを置くため必須。どのフェーズより先に着手してよい。
- [ ] フッターに「デモ環境 — データはすべて架空です」の注記を追加（`src/components/layout/Sidebar.tsx` フッター、またはレイアウト全体の共通フッター）。
- [ ] 実名・実金額を使わない方針は各フェーズ計画内で担保済み（イニシャル表記＋架空値）。

### Phase 0ヒアリングで確認してから反映する項目（先走り注意 — 原文spec末尾）

以下は現時点の各計画内で「暫定値」として仮置きしている箇所。ヒアリング後に差し替えること：

- 在庫管理・自動実行管理の実態（現状ハイライト対象外、機能追加なし）
- 楽楽明細向けExcel加工の不足項目リスト → P2 Task1 Step5の暫定リストを実物に差し替え
- 都度請求の現状発行手順 → P0で `billingType: '都度請求'` を用意したのみ、都度請求ボタンの挙動は未設計
- 単価マスタ運用の切り分け基準（正規商品 vs 汎用商品）→ 本アプリに品目マスタ自体が存在しないため、導入する場合は別途データモデル設計が必要
- 未入金分請求書のレイアウト・発行タイミング → P1 Task2 Step3の暫定実装を実物要件に合わせて調整

## 実装方法

各計画ファイルは `superpowers:subagent-driven-development` または `superpowers:executing-plans` で単独実行可能。P0から順に実行することを推奨（他フェーズがP0の新id・新データに依存するため）。
